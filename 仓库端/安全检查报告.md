# 仓库端安全性检查报告

检查对象：`仓库端/warehouse-001.html`

## 严重（必须尽快处理）

### S1. 匿名 API key 可直接读出全部账号明文密码
- **证据**：`GET /rest/v1/accounts?select=*`（anon）返回 200，含 `username/password/role`
- **实测泄漏账号**：`xiexiexie`(wh_admin)、`staff1`、`sale1`，密码为明文短字符串
- **影响**：任何人打开网页/拿到 HTML 即可接管仓库、销售、管理员账号
- **根因**：
  1. `accounts` 表 RLS 未启用（`商品重构_migration.sql` 中 `ENABLE ROW LEVEL SECURITY` 仍被注释）
  2. 前端 `loadAllData()` 执行 `sb.from('accounts').select('*')` 把密码拉进浏览器内存
  3. 登录为前端明文比对：`x.u===u && x.p===p`

### S2. 匿名 key 可写商品/分类
- **证据**：anon 对 `products` UPDATE 204、INSERT 201；对 `categories` INSERT/UPDATE/DELETE 均可
- **影响**：可篡改价格、库存、SKU、分类，甚至删库式破坏
- **实测已清理**：临时分类 `ZZSEC1`、临时商品 `ZZSEC99`、商品 note 探测值均已恢复/删除

### S3. 密码明文存储
- **证据**：`accounts.password` 长度 7–8，非 bcrypt/argon2/pbkdf2；创建账号直接 `insert({password: p})`
- **影响**：即使收了 RLS，一旦库被读仍全部沦陷

## 高危

### H1. 前端硬编码 anon key（预期内但放大 S1/S2）
- `SB_KEY = 'eyJ...'` 写在 HTML 里；配合错误 RLS 等于公开数据库

### H2. 登录无速率限制 / 无锁定
- `doLogin()` 失败仅提示错误，无失败计数、验证码、锁定

### H3. 会话仅存 id，恢复时不校验密码
- `sessionStorage.cs4 = {id, pl}`；刷新后只要 `accounts.status==='active'` 即自动登录
- 本机 XSS 或共用电脑可轻易冒用已登录角色

### H4. 客户全量 `select('*')`
- `customers` 等表整表进前端；字段虽映射时未取 password，但 RLS 未锁前接口层仍可读（当前 anon 对 customers 返回 404，疑似表权限/暴露配置，不稳定）

---

## 中危

### M1. 商品图 `p.img` 未转义拼进 HTML
```js
'<img src="' + p.img + '" alt="" onerror="this.remove()">'
```
- 若 `img` 字段被写入 `x" onerror="...` 或 `javascript:` URL，可形成 XSS（与 S2 叠加可自写自触发）

### M2. 登录/账号接口全部在浏览器完成
- `has(k)` 权限判断仅前端；禁用 JS 或直接调 Supabase 即可绕过 UI 限制

### M3. 外链 CDN `supabase-js`
- `cdn.jsdelivr.net` 被劫持或离线会影响应用完整性（有 onerror 兜底但不校验 SRI）

---

## 低危 / 观察

- L1. `esc()` 实现正确（textContent→innerHTML），文本插值多数有转义
- L2. 未使用 `eval` / `new Function` / `javascript:` 伪协议
- L3. `service_role` key **不在** HTML 中（仅 `数据库端/secrets.local.json`），切勿提交仓库或部署到静态站
- L4. 订单/出入库表 anon 当前 404，但仍应按「已公开」设防
